=> goroutines : 
   one single os thread has many goroutines. Go runtime manages their execution on single os thread. but that os thread 
   itself is managed by os only. context switching b/w os thread is costlier but b/w goroutines is cheaper. 
   stack size of goroutines : 2 kb , os thread : 8 MB

=> waitgroup is to ensure ki main thread wait kare 

  wg.Add(1) : increases counter by 1 
  wg.Done() : decreases counter by 1 
  wg.wait() : wait until counter become 0 


=> always use Add() before go func() because func ke andar hi add karein toh ho sakta ki schedule na ho 
   aur jab Done() call karo toh defer wg.Done() .

=> 	for i := 1; i <= 3; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println(i)
		}()
	}
	wg.Wait()

   for this code goroutines operate on current value of their variables. If we want to use any other state we need to pass 
   that as parameter to function. isme (i) pass karenge nahi toh 4 print hoga.

=> Go Runtime has mechanism called MN scheduler.
 
  N goroutines can be scheduled on M OS threads that runs on at max GOMAXPROCS number of processors.

 As of Go 1.14 , each goroutines is given a time slice of 10ms.
